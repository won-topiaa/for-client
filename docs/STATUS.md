## v1.3.5 — 차트 사진 분석

흐름: **사진 업로드(종목 필수) → 분석 → 설명 전달.** 자세한 건 서버 저장소 `docs/PHOTO_ANALYSIS.md`.

- 숫자·판정은 전부 서버 엔진이 그 종목의 최신 데이터로 계산한다. 사진에서 숫자를 읽지 않는다.
- 지표는 **차트 모양 말고는 전부** 보여 준다: 지지선 · 이평선 배열 · 150일선 흐름 · 1년 범위 ·
  RSI · MACD · 볼린저 · ATR · 거래량 · OBV (일 · 주 · 월). 차트 모양은 감지될 때만.
- 차트 모양 9종: 헤드앤숄더 · 역헤드앤숄더 · 삼각수렴 · 컵앤핸들 · 초기 상승추세 +
  새로 **쌍봉 · 쌍바닥 · 박스권 · 쐐기형**.
- AI(저가 비전 모델)는 '사진에서 보이는 것' 한두 문장과 사실 풀이만 한다. 전망·권유·계좌
  정보가 섞인 문장은 서버가 버린다. 키가 없거나 실패하면 템플릿 설명(엔진 문장)이 나간다.
- 비용: 분석 1회 약 1~3원 (gemini-3.1-flash-lite / gpt-6-luna). 하루 LLM 400회 상한 = 최대 약 1,000원/일.
- 사진은 저장·로그 기록하지 않는다. 개인정보처리방침 개정(2026-09-25): 사진 미저장 · 횟수 확인 ·
  AI 제공업체(미국) 전송.
- 권한: photos(read) · camera(access). 하루 10번/사람.

## 고친 것: 미국 스캔이 28개로만 돌던 문제 (2026-09-25)

'오늘의 지지선' · '차트 패턴'의 미국 탭이 **28종목**만 훑고 있었다(국내는 300).
설계는 S&P500 − 메가캡 29 = 약 475종목이다. 운영에서 위키피디아 S&P500 목록 받기가
줄곧 실패해 비상 목록 28개로 떨어졌고, 실패가 로그 없이 삼켜져 드러나지 않았다.

- 서버에 S&P500 스냅숏(`app/data/sp500.csv`, 503종목)을 넣었다. 목록을 못 받으면 이걸로 스캔한다.
  몇 달에 한 번 `python scripts/update_sp500.py` 로 갱신해 커밋하면 된다.
- 목록 받기를 위키미디어 정책에 맞는 User-Agent 로 바꿨다(가장 유력한 실패 원인).
  실패하면 Render 로그에 `S&P500 목록 받기 실패 — …` 가 남고, 스캔마다
  `미국 유니버스 N종목 (실시간 목록/내장 스냅숏)` 이 남는다.
- 로컬 실측(475종목): 지지선 스캔 약 2.5분, 패턴 17초, 메모리 +약 90MB.

## 서버에 이미 들어간 것 (`ma-radar` @ `f388306`)

이건 앱 심사와 무관하게 **지금 살아 있다.** 구버전 앱도 깨지지 않도록 전부
기존 응답에 필드를 더하는 방식으로 넣었다.

- `GET /api/today` — 아침 브리핑 요약 + 한/미 지지선 스캔 상태 + `refreshAtKst`
- `POST /api/push/watchlist` — 관심종목 심볼만 저장 (최대 30개, 병합 아닌 교체)
- `/api/push/status` 에 `watchCount` 추가
- `/api/lines` 로그인 게이트 제거 — 앱에서 바로 호출 가능
- 아침 발송이 관심종목 보유자에게 개인 문구를 섞어 보냄 (`_PUSH_BODY_MAX = 25`)
- `static/privacy.html` · `static/i18n.js` 관심종목 알림 관련 조항 한/영 개정

`/api/today` 가 `refreshAtKst` 를 같이 내려준다. 앱은 이 값을 **문구와 경계 계산
양쪽에** 쓴다 — 갱신 시각을 앱에 적어 두지 않는다. `src/refreshDay.ts` 참조.

## 갱신 시각은 서버가 정한다

한때 앱이 06:30 을 적어 두고 있었다. 홈 브리핑 카드는 서버가 준 `refreshAtKst` 로
문구를 그리는데 관심종목 '오늘 지지선' 배지는 그 하드코딩으로 오늘/어제를 갈라서,
서버의 `DAILY_REFRESH_KST` 를 바꾸면 같은 앱의 두 화면이 서로 다른 날짜를 말하게
돼 있었다. 지금은 한 곳으로 모았다.

- `src/refreshDay.ts` — 경계의 단일 출처. `/api/today` 응답에서 배우고,
  저장해 뒀다가 다음 콜드 스타트에서 되살린다(응답이 오기 전의 틈을 메운다).
- `api/client.ts` 의 `fetchToday()` 가 배움을 먹인다 — 화면마다 따로 부를 필요가 없다.
- `pages/watchlist.tsx` 는 `useRefreshDayKey()` 를 쓴다. 경계를 새로 배우면 키가
  바뀌고, 옛 경계로 담아 둔 캐시는 그 자리에서 무효가 된다.
- `env.ts` 에는 시각 상수가 없다. 찾는 사람이 `refreshDay.ts` 로 가도록 주석만 남겼다.

서버가 값을 안 주거나(구버전) 형식이 깨진 값을 주면 쓰던 값을 그대로 둔다.
부팅값 06:30 은 서버 기본값과 같게 맞춰 둔 출발점일 뿐이고, 진실이 아니다.
